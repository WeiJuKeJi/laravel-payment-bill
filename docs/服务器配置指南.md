# 服务器配置指南

本文档说明部署 Laravel Payment Bill 扩展包时需要的服务器配置。

## PHP 配置

### 文件上传配置

如果需要批量上传大量账单文件，需要调整 PHP 的文件上传配置。

#### 找到 php.ini 文件

```bash
# 查找 php.ini 位置
php --ini

# 或者
php -i | grep php.ini
```

#### 修改配置项

编辑 `php.ini` 文件，调整以下参数：

```ini
; 单个文件最大上传大小
upload_max_filesize = 20M

; POST 数据最大大小（应该大于 upload_max_filesize）
post_max_size = 100M

; 允许同时上传的文件数量（重要！）
; 如果需要上传超过1000个文件，请增加此值
max_file_uploads = 2000

; 脚本最大执行时间（秒）
max_execution_time = 300

; POST/GET 请求的最大输入变量数
max_input_vars = 5000

; 内存限制
memory_limit = 256M
```

#### 重要参数说明

| 参数 | 默认值 | 推荐值 | 说明 |
|------|--------|--------|------|
| `upload_max_filesize` | 2M | 20M | 单个文件最大大小 |
| `post_max_size` | 8M | 100M | 整个 POST 请求的最大大小 |
| `max_file_uploads` | 20 | 2000+ | **同时上传的文件数量限制** |
| `max_execution_time` | 30 | 300 | 脚本执行超时时间 |
| `max_input_vars` | 1000 | 5000+ | 输入变量数量限制 |
| `memory_limit` | 128M | 256M | PHP 脚本内存限制 |

**重点：** `max_file_uploads` 参数很重要！如果你需要上传1000+个历史账单文件，必须将此值设置为大于文件数量的值。

#### 重启服务

修改配置后，需要重启 PHP-FPM 或 Web 服务器：

```bash
# PHP-FPM
sudo systemctl restart php8.2-fpm
# 或
sudo service php8.2-fpm restart

# Nginx
sudo systemctl restart nginx
# 或
sudo nginx -s reload

# Apache
sudo systemctl restart apache2
# 或
sudo service apache2 restart
```

#### 验证配置

创建测试文件 `phpinfo.php`：

```php
<?php
phpinfo();
```

访问该文件，搜索 `max_file_uploads`、`upload_max_filesize` 等参数，确认配置已生效。

**记得删除测试文件：**
```bash
rm phpinfo.php
```

## Nginx 配置

### 客户端请求体大小限制

编辑 Nginx 配置文件（通常在 `/etc/nginx/nginx.conf` 或 `/etc/nginx/sites-available/your-site`）：

```nginx
server {
    # ... 其他配置

    # 允许上传大文件（应与 PHP post_max_size 匹配或略大）
    client_max_body_size 100M;

    # 请求体缓冲大小
    client_body_buffer_size 128k;

    # 超时设置
    client_body_timeout 300s;
    send_timeout 300s;

    # FastCGI 超时设置（针对 PHP-FPM）
    location ~ \.php$ {
        fastcgi_read_timeout 300s;
        fastcgi_send_timeout 300s;

        # ... 其他 FastCGI 配置
    }
}
```

重启 Nginx：
```bash
sudo nginx -t  # 测试配置
sudo systemctl restart nginx
```

## Apache 配置

### 文件上传大小限制

编辑 Apache 配置或 `.htaccess` 文件：

```apache
# 限制请求体大小
LimitRequestBody 104857600  # 100MB in bytes

# PHP 配置（如果使用 mod_php）
php_value upload_max_filesize 20M
php_value post_max_size 100M
php_value max_execution_time 300
php_value max_input_time 300
php_value memory_limit 256M
php_value max_file_uploads 2000
```

重启 Apache：
```bash
sudo systemctl restart apache2
```

## 常见问题排查

### 问题1：上传失败，提示 "Maximum number of allowable file uploads has been exceeded"

**原因：** PHP 的 `max_file_uploads` 配置值太小。

**解决：**
1. 编辑 `php.ini`，增加 `max_file_uploads` 的值
2. 重启 PHP-FPM
3. 验证配置是否生效

```bash
# 快速检查当前值
php -r "echo ini_get('max_file_uploads');"
```

### 问题2：上传超时

**原因：** PHP 或 Web 服务器的超时时间太短。

**解决：**
1. 增加 PHP 的 `max_execution_time`
2. 增加 Nginx 的 `fastcgi_read_timeout` 或 Apache 的超时配置
3. 考虑分批上传文件

### 问题3：内存不足

**原因：** 上传大量文件时内存占用过高。

**解决：**
1. 增加 PHP 的 `memory_limit`
2. 考虑使用队列异步处理
3. 减少单次上传的文件数量

### 问题4：413 Request Entity Too Large

**原因：** Nginx 的 `client_max_body_size` 太小。

**解决：**
```nginx
client_max_body_size 100M;
```

### 问题5：上传后文件丢失

**原因：** PHP 临时目录空间不足或权限问题。

**解决：**
```bash
# 检查临时目录
php -r "echo sys_get_temp_dir();"

# 检查磁盘空间
df -h

# 检查权限
ls -la /tmp

# 清理临时文件
sudo rm -rf /tmp/php*
```

## Docker 环境配置

如果使用 Docker，可以通过自定义 PHP 配置文件：

### Dockerfile

```dockerfile
FROM php:8.2-fpm

# 复制自定义 PHP 配置
COPY custom-php.ini /usr/local/etc/php/conf.d/custom-php.ini

# ... 其他配置
```

### custom-php.ini

```ini
upload_max_filesize = 20M
post_max_size = 100M
max_file_uploads = 2000
max_execution_time = 300
max_input_vars = 5000
memory_limit = 256M
```

### docker-compose.yml

```yaml
services:
  php:
    build: .
    volumes:
      - ./custom-php.ini:/usr/local/etc/php/conf.d/custom-php.ini:ro
```

## 性能优化建议

### 1. 使用 OpCache

```ini
; php.ini
opcache.enable=1
opcache.memory_consumption=128
opcache.interned_strings_buffer=8
opcache.max_accelerated_files=10000
opcache.revalidate_freq=2
```

### 2. 调整 PHP-FPM 进程数

编辑 `/etc/php/8.2/fpm/pool.d/www.conf`：

```ini
; 进程管理方式
pm = dynamic

; 启动时的进程数
pm.start_servers = 5

; 最小空闲进程数
pm.min_spare_servers = 5

; 最大空闲进程数
pm.max_spare_servers = 10

; 最大进程数
pm.max_children = 20
```

### 3. 使用队列处理大批量文件

对于超大批量文件（1000+），建议使用 Laravel 队列异步处理：

```php
// 在 Controller 中
foreach (array_chunk($files, 100) as $chunk) {
    ProcessBillFilesJob::dispatch($chunk);
}
```

## 生产环境检查清单

部署前请确认以下配置：

- [ ] `max_file_uploads` >= 预期上传的最大文件数
- [ ] `upload_max_filesize` >= 单个文件的最大大小
- [ ] `post_max_size` > `upload_max_filesize` * `max_file_uploads`
- [ ] `max_execution_time` 足够处理所有文件
- [ ] `memory_limit` 足够大
- [ ] Nginx/Apache 的请求大小限制已调整
- [ ] 磁盘空间充足（临时目录和存储目录）
- [ ] PHP-FPM 进程数配置合理
- [ ] 日志记录已启用，便于问题排查

## 监控和日志

### 启用 PHP 错误日志

```ini
; php.ini
log_errors = On
error_log = /var/log/php/php-errors.log
error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT
```

### Laravel 日志

```php
// 记录上传信息
Log::info('File upload started', [
    'file_count' => count($files),
    'memory_usage' => memory_get_usage(true),
]);
```

### 系统监控

```bash
# 监控 PHP-FPM 进程
ps aux | grep php-fpm

# 监控内存使用
free -h

# 监控磁盘使用
df -h

# 实时监控日志
tail -f /var/log/php-fpm/error.log
tail -f /var/log/nginx/error.log
tail -f storage/logs/laravel.log
```
