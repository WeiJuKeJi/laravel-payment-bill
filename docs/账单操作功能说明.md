# 账单操作功能说明

本文档详细说明账单下载记录的三个操作功能。

## 功能概览

| 功能 | 端点 | 方法 | Controller 方法 | 说明 |
|------|------|------|----------------|------|
| 下载文件到浏览器 | `/bill-downloads/{id}/file` | GET | `downloadFile()` | 将服务器上的账单文件下载到用户电脑 |
| 重新下载账单 | `/bill-downloads/{id}/download` | POST | `download()` | 从支付平台重新下载账单文件到服务器 |
| 重新导入数据 | `/bill-downloads/{id}/import` | POST | `import()` | 将账单文件数据重新解析并导入数据库 |

## 金额口径说明

账单下载记录中的订单金额、退款金额和结算金额统一按以下口径展示：

- 订单金额：支付交易总额，不扣减退款行。
- 退款金额：退款交易绝对金额。
- 结算金额：支付交易与退款交易轧差后的商家实收金额。

支付宝业务明细中退款行的订单金额通常为负数，导入时只计入退款金额，不再抵减订单金额；支付宝业务汇总文件若给出的是退款后净额，账单下载记录会使用明细重算的支付交易总额展示。

## 下载状态说明

| 状态 | 含义 | 是否进入失败重试 |
|------|------|------------------|
| `pending` | 等待下载 | 否 |
| `processing` | 正在下载 | 否 |
| `completed` | 已成功下载账单文件 | 否 |
| `no_statement` | 支付平台明确确认当日无账单文件 | 否 |
| `failed` | 下载参数、网络、鉴权或平台接口等原因导致真正失败 | 是 |

微信返回 `NO_STATEMENT_EXIST` 时，下载服务会将记录保存为 `no_statement`，金额与交易数量归零、导入状态直接完成，不生成账单文件。该状态用于和没有下载记录的日期、真正的下载失败分别展示。

## 1. 下载文件到浏览器

### 功能说明
将服务器上已保存的账单文件下载到用户的电脑中。

### API 端点
```
GET /api/payment-bill/bill-downloads/{id}/file
```

### 使用示例
```bash
curl -X GET "https://your-domain.com/api/payment-bill/bill-downloads/1216/file" \
  -H "Authorization: Bearer {token}" \
  -O -J
```

### 前置条件
- ✅ 账单下载状态为 `completed`
- ✅ 账单文件路径存在
- ✅ 文件在存储中实际存在

### 响应
- **成功**：返回文件流（浏览器会自动下载）
- **失败**：返回 JSON 错误信息

### 文件命名规则
生成的文件名格式：`{渠道}_{日期}_{类型}.{扩展名}`

示例：`wechat_20220724_ALL.csv`

## 2. 重新下载账单

### 功能说明
从支付平台（微信/支付宝）重新下载该账单文件到服务器，会覆盖原有文件。

### API 端点
```
POST /api/payment-bill/bill-downloads/{id}/download
```

### 使用示例
```bash
curl -X POST "https://your-domain.com/api/payment-bill/bill-downloads/1216/download" \
  -H "Authorization: Bearer {token}" \
  -H "Accept: application/json"
```

### 前置条件
- ✅ 账单记录存在
- ✅ 支付渠道信息完整

### 响应示例
```json
{
  "code": 200,
  "msg": "账单下载任务已派发",
  "data": {
    "id": 1216,
    "payment_channel_id": 1,
    "bill_date": "2022-07-24",
    "bill_type": "ALL",
    "download_status": "pending",
    "file_path": "payment/bills/wechat/1/20220724.csv",
    "downloaded_at": null
  }
}
```

### 使用场景
- 账单下载失败，需要重新下载
- 账单文件已损坏或丢失
- 需要获取最新的账单数据

### 处理流程
1. 验证支付渠道信息
2. 调用 `BillDownloadService::download()` 并设置 `force: true`
3. 更新账单状态为 `pending`
4. 异步下载文件
5. 更新状态和文件路径

## 3. 重新导入数据

### 功能说明
将账单文件数据重新解析并导入到账单明细表（`wechat_bills` 或 `alipay_bills`），会覆盖已存在的数据。

### API 端点
```
POST /api/payment-bill/bill-downloads/{id}/import
```

### 使用示例
```bash
curl -X POST "https://your-domain.com/api/payment-bill/bill-downloads/1216/import" \
  -H "Authorization: Bearer {token}" \
  -H "Accept: application/json"
```

### 前置条件
- ✅ 账单下载状态为 `completed`
- ✅ 账单文件路径存在
- ✅ 文件在存储中实际存在
- ✅ 支付渠道信息完整

### 响应示例
```json
{
  "code": 200,
  "msg": "微信账单导入任务已派发",
  "data": {
    "id": 1216,
    "payment_channel_id": 1,
    "bill_date": "2022-07-24",
    "bill_type": "ALL",
    "download_status": "completed",
    "import_status": "pending",
    "file_path": "payment/bills/wechat/1/20220724.csv",
    "file_size": 1024000,
    "downloaded_at": "2022-07-25 10:00:00",
    "imported_at": null,
    "payment_channel": {
      "id": 1,
      "name": "微信支付渠道",
      "channel": "wechat",
      "is_enabled": true
    }
  }
}
```

### 使用场景
- 账单数据导入失败
- 账单文件有更新，需要重新解析
- 数据异常，需要重新导入

### 处理流程
1. 验证账单文件状态和存在性
2. 根据渠道类型调用相应的导入服务：
   - 微信：`BillImportService::dispatchWechatImport()`
   - 支付宝：`BillImportService::dispatchAlipayImport()`
3. 设置 `force: true` 强制覆盖
4. 更新导入状态为 `pending`
5. 异步解析并导入数据

## 错误处理

### 通用错误

| 错误码 | 错误信息 | 说明 |
|--------|---------|------|
| 400 | 账单文件尚未下载完成 | 下载状态不是 completed |
| 400 | 账单文件路径不存在 | file_path 字段为空 |
| 400 | 账单缺少关联的支付渠道信息 | paymentChannel 关系为空 |
| 400 | 不支持的支付渠道类型 | 渠道不是 wechat 或 alipay |
| 404 | 账单文件不存在 | 文件在存储中不存在 |
| 404 | 账单记录不存在 | 路由参数 ID 无效 |
| 500 | 任务派发失败 | 系统异常 |

### 重新下载特有错误

微信返回 `NO_STATEMENT_EXIST` 不作为错误返回，而是将记录更新为 `no_statement`。对该记录再次强制下载时，若支付平台后续已生成账单，则可正常更新为 `completed`。

### 重新导入特有错误

| 错误码 | 错误信息 | 说明 |
|--------|---------|------|
| 404 | 账单文件不存在或已被删除 | 文件在配置的存储磁盘中不存在 |

## 代码风格说明

### 统一的编码风格

1. **方法命名**：
   - `downloadFile()` - 动词 + 名词
   - `download()` - 简洁动词
   - `import()` - 简洁动词

2. **响应格式**：
   - 统一使用 `respondWithResource()` 返回完整的资源对象
   - 保持与其他 CRUD 操作（index, show, store）一致
   - 前端获得统一的数据结构

3. **注释风格**：
   ```php
   /**
    * 方法说明（中文）
    *
    * 详细描述（可选）
    */
   ```

4. **错误信息**：
   - 简洁明了的中文提示
   - 不包含技术细节
   - 便于前端直接显示

5. **数据加载**：
   - 统一使用 `loadMissing('paymentChannel')` 预加载关联
   - 放在方法开头

6. **验证顺序**：
   - 先检查关联数据（如支付渠道）
   - 再检查状态
   - 最后检查文件

7. **异常处理**：
   ```php
   try {
       // 业务逻辑
   } catch (\InvalidArgumentException $e) {
       return $this->error($e->getMessage(), 400);
   } catch (\Exception $e) {
       return $this->error('操作失败：'.$e->getMessage(), 500);
   }
   ```

## 与命令行工具的关系

| 功能 | Web API | 命令行工具 |
|------|---------|-----------|
| 下载文件到浏览器 | `GET /bill-downloads/{id}/file` | - |
| 重新下载账单 | `POST /bill-downloads/{id}/download` | `php artisan payment-bill:download --force` |
| 重新导入数据 | `POST /bill-downloads/{id}/import` | `php artisan payment-bill:import --force` |

**区别：**
- Web API：针对单个账单记录操作
- 命令行工具：批量处理，支持日期和渠道过滤

## 最佳实践

### 1. 操作顺序

正常流程：
```
1. 创建账单下载记录
   POST /bill-downloads

2. 等待下载完成（异步）

3. 检查下载状态
   GET /bill-downloads/{id}

4. 下载文件到本地（可选）
   GET /bill-downloads/{id}/file
```

重新处理流程：
```
1. 如果下载失败或需要更新：
   POST /bill-downloads/{id}/download

2. 如果导入失败或需要重新导入：
   POST /bill-downloads/{id}/import
```

### 2. 错误处理

前端应该处理以下情况：
- 账单未下载完成：提示用户等待或重新下载
- 文件不存在：提示用户重新下载
- 渠道信息缺失：联系管理员配置

### 3. 异步任务监控

所有操作都是异步的，建议：
- 轮询账单状态
- 使用 WebSocket 实时通知
- 提供任务队列查看功能

## 安全考虑

1. **认证授权**：
   - 所有端点都需要 Sanctum 认证
   - 建议添加权限检查

2. **文件访问**：
   - 文件路径不直接暴露给前端
   - 通过控制器统一下载
   - 验证用户权限

3. **操作限制**：
   - 考虑添加频率限制
   - 记录操作日志
   - 异常情况告警
